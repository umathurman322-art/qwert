# Техническое задание: Telegram-бот магазина Adopt Me / Robux

**Проект:** `adoptme-shop-bot`  
**Платформа:** Telegram Bot API  
**Стек:** Python 3.11+, aiogram 3.x, SQLite (aiosqlite), опционально Mini App (WebApp)  
**Роли:** Пользователь, Саппорт, Администратор

---

## 1. Цель продукта

Автоматизированный магазин внутри Telegram:

- продажа петов Adopt Me и робуксов (Robux);
- скупка петов и робуксов по заявкам;
- личный кабинет, рефералка, тикеты поддержки;
- админ-панель внутри бота и рабочие чаты менеджеров со связкой через Reply.

Бот не выполняет внутриигровые действия в Roblox. Передача товара — ручная (игры/трейд), бот только проводит заявки, оплату и чат передачи.

---

## 2. Роли и доступы

| Роль | Как назначается | Права |
|---|---|---|
| Пользователь | любой, прошедший капчу | меню, покупка, продажа, ЛК, поддержка |
| Саппорт | `role=support` в БД или работа в чате поддержки | ответы Reply в support-чате, просмотр тикетов |
| Администратор | `ADMIN_IDS` в `.env` + `role=admin` | `/admin`, курсы, каталог, тексты, рассылка, статистика, кнопки тикетов |

Админы из `ADMIN_IDS` капчу не проходят. Остальные — только после капчи.

---

## 3. Сценарии пользователя

### 3.1. Старт и капча

1. `/start` создаёт запись пользователя (если нет).
2. Если `captcha_passed=0` — выдаётся текстовая (пример: `7 + 12 = ?`) **или** графическая капча (картинка с 4 цифрами).
3. Middleware блокирует любые другие сообщения/колбэки до успеха.
4. Неверный ответ — новая капча. Успех — главное меню.
5. Реферальный параметр: `/start ref_<tg_id>`.

### 3.2. Главное меню

1. 🛒 Купить  
2. 💰 Продать  
3. 👤 Личный кабинет  
4. ☎️ Поддержка  
5. 🛡️ Правила / Отзывы  

### 3.3. Купить — петы

- Каталог: Inline-кнопки **или** WebApp (если задан `WEBAPP_URL` с HTTPS).
- Фильтры: редкость, тип (Normal / Neon / Mega-Neon), ценовой диапазон, пагинация.
- Карточка: название, редкость, тип, цена, наличие.
- «Купить» → заявка `buy_pet` → реквизиты → «Я оплатил» → уведомление админам.
- После подтверждения оплаты админом открывается диалог передачи товара.

### 3.4. Купить — робуксы

- Показ курса продажи (`robux_sell_rate`: сколько R$ за 1 ₽).
- Калькулятор в обе стороны (рубли ↔ Robux).
- Заявка `buy_robux` + реквизиты + подтверждение оплаты.

### 3.5. Продать — петы (FSM)

Состояния: название → количество → желаемая цена → торг Да/Нет.  
Тикет в **чат администраторов** с кнопками Принять / Отклонить / Начать диалог.

### 3.6. Продать — робуксы

Количество + способ передачи. Выплата = `amount / robux_buy_rate` (курс скупки: сколько R$ за 1 ₽ выплаты).  
Тикет в чат админов.

### 3.7. Личный кабинет

Баланс (внутренний, для учёта), история сделок, реферальная ссылка `t.me/<bot>?start=ref_<id>`.

### 3.8. Поддержка

Пользователь пишет текст/фото → тикет в **чат поддержки**. Дальше — анонимный мост Reply (п. 4).

---

## 4. Мост Reply (ядро поддержки)

1. Бот публикует карточку тикета в `ADMIN_CHAT_ID` или `SUPPORT_CHAT_ID`.
2. В БД: `ticket_links(chat_id, message_id) → ticket_id` для **каждого** сообщения ветки.
3. Менеджер жмёт Reply на любое сообщение ветки → бот отправляет текст/фото пользователю от имени бота.
4. Сообщение пользователя (не команда и не кнопка меню), если есть активный диалог, уходит реплаем в рабочий чат на исходный тикет.
5. Кнопки: `✅ Принять`, `❌ Отклонить`, `💬 Начать диалог`.
6. Пользователь не видит username менеджера; менеджер видит `tg_id` и `@username` в карточке.

---

## 5. Админ-панель `/admin`

- Курсы: продажа и скупка Robux.
- Каталог: добавить / изменить цену / наличие / удалить.
- Тексты: приветствие, правила, отзывы, реквизиты.
- Рассылка: текст или фото всем пользователям (с паузой антифлуда).
- Статистика: пользователи, сделки, оборот.

---

## 6. Модель данных (SQLite)

- `users` — профиль, роль, капча, баланс, реферер.  
- `settings` — курсы и редактируемые тексты.  
- `products` — петы.  
- `orders` — заявки купить/продать.  
- `tickets`, `ticket_links` — тикеты и привязка message_id.  
- `deal_logs` — история для ЛК.

Схема создаётся при старте. PostgreSQL: тот же SQL + драйвер asyncpg/SQLAlchemy; в v1 рабочий движок — SQLite.

---

## 7. Нефункциональные требования

- Модульность: handlers / keyboards / states / db / middlewares / services.  
- Тексты в `app/texts.py` + override из `settings`.  
- Ошибки ввода (буквы вместо числа) не роняют бот.  
- Внешний error-middleware логирует апдейты.  
- Секреты только в `.env`.

---

## 8. Запуск (критерии готовности)

1. Заполнен `.env` (токен, admin id, id рабочих чатов).  
2. Бот добавлен в чаты админов/саппорта, выданы права на сообщения.  
3. `pip install -r requirements.txt` → `python run.py`.  
4. `/start` → капча → меню.  
5. Анкета продажи появляется в админ-чате, Reply доходит до пользователя.  
6. `/admin` доступен только ID из конфига.
